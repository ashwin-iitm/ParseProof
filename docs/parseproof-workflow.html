How ParseProof checks a document

OpenAI extracts every field once. Then each value is checked against the page it came from by a second, independent model, and plain Python code makes sure neither model made anything up. A person only looks at the fields that didn't check out.

The workflow

Python code (no AI) OpenAI extractor (gpt-4.1) Second model, the checker (gpt-4o) A person

In plain words

  1. Extract once. OpenAI reads the whole document and returns every field with three things: the value, the page it is on, and an exact quote copied from that page.
  2. Find the right page. Python checks that the quote really is on the page the extractor named. If it isn't, the RAG index (built from the document's pages when it was uploaded) searches for the one to three pages most likely to contain that field.
  3. Check with a second model. A different model gets only those pages, as text and as images, plus the extracted value. It answers correct, incorrect (and gives the right value), or not found, and it must quote its evidence.
  4. Check the checker. Python confirms the checker's quote really exists on that page, and that any correction it suggests actually appears in the quote. If not, the field goes to a person.
  5. Review the exceptions. Rule checks run across all fields, then a person reviews only the flagged fields, each shown on its page with the evidence highlighted.

It does not extract twice and compare

Not this

Extract with OpenAI, extract again with our own code, then compare the two answers. Our code doesn't read values out of documents at all.

This

Extract once with OpenAI, then verify each value. Our code (the RAG search and the quote checks) decides where to look and whether the proof is real. The second model decides whether the value matches the page.

One field, start to finish

A real catch from testing: the supplier's tax ID (GSTIN) on a scanned two-page invoice.
  1. Python

    Page 1 has no text layer, so it's read with OCR and added to the RAG index.

  2. Extractor

    Returns 29AAMCM471Q1Z6, page 1. It misread the scan: two characters swapped and one dropped.

  3. Python

    Finds the extractor's quote on page 1, so page 1 is the page to check. No search needed.

  4. Checker

    Reads page 1 and answers incorrect: the page says 29AAKCM4471Q1Z6, quoting “GSTIN: 29AAKCM4471Q1Z6”.

  5. Python

    Confirms that quote is on page 1 and that the corrected value is inside it. The field is marked Mismatch.

  6. Person

    Sees one flagged field out of eleven, with page 1 open. Clicks “Use verified value” and approves. The export carries the correct GSTIN.

Questions colleagues ask

Why not ask the same model to check itself?

A model tends to repeat its own mistakes. A different model, looking only at the one page, is a real second opinion.

What if the extractor names the wrong page?

Python searches the whole document for the extractor's quote. If the quote isn't found, the RAG index finds the likeliest pages. The report notes that the citation was wrong.

Does it work on scanned documents?

Yes. Pages with no text are read with OCR so they can be searched and checked. On scans the evidence shows as a quote beside the field rather than highlighted on the page.

Do I still need to look at everything?

No. Verified fields have been confirmed on their source page with real evidence. You review the Mismatch and Needs review fields, then approve.

What can't it do yet?

Each field is one value. Repeating tables, like every line item or every claim on a loss run, are captured as totals and counts rather than row by row.
