Short answers to common questions

Does Python read the PDF and send its text to the AI that extracts the data? No. The extractor gets the PDF file itself.

For a PDF, gpt-4.1 receives the actual file. OpenAI reads its text and looks at a picture of every page, so tables, stamps and scans work. For Excel, Word and CSV it's different: Python turns them into text first, and that text is sent.

Then what does Python do with the pages? It reads every page and sends all the text to OpenAI's embedding model.

Before extraction starts, Python takes the text of every page and sends it to text-embedding-3-small, which turns each page into 1,536 numbers. Those numbers and a word count of each page become the search index. The index is only used later, by the QC checker, to find pages and to check quotes.

If Python finds the exact quote on the page, does the checker AI still run? Yes. Every field gets a gpt-4.1-mini check.

Python can prove a sentence is on page 41. It can't tell whether that sentence answers the field: the flood deductible is a real sentence, but not the policy's deductible. The only time no checker AI runs is when no page can be found at all.

Does the checker AI read the whole document? No. Usually just the one page each answer came from.

It gets that page's text, with all the fields found on it in one call. Empty fields are checked on up to 4 pages the search finds; a field that still isn't confirmed gets its page plus up to 3 searched pages, with up to 2 page pictures. That keeps it focused and cheap.

PDF versus Excel or Word

Step by step, with the policy

You upload the file

Python

Handing the policy to the office.

The server saves policy.pdf in data/documents/, checks it is a PDF, Word, Excel, CSV or text file under 100 MB, counts its 60 pages, and refuses it straight away if it is password-protected. You pick the Insurance policy template and click Extract and verify.

Sent to OpenAI: nothing.

Python reads the text of every page

Python

Photocopying every page so you can search it later.

PyMuPDF takes each page's text in blocks, top to bottom and left to right, so a column stays together. For an Excel or CSV file each row becomes one “page”; for Word, each paragraph; a text file is one page. A PDF page with fewer than 25 characters of text is treated as a scan.

Sent to OpenAI: nothing yet.

OCR for scanned pages

gpt-4.1-mini

Someone types out the one page that was a photo.

Page 58 is a scan. Python draws it as a picture (150 dots per inch) and sends it to gpt-4.1-mini with the instruction “Transcribe all text on this page exactly”. The typed text replaces the empty page in Python's text. If several pages are scans, up to 8 are done at the same time.

Sent to OpenAI: a picture of page 58 only.

Python sends all page text to the embedding model, and builds the index

Pythontext-embedding-3-small

Writing the index at the back of the book, before anyone asks a question.

  • Python sends the text of all 60 pages to OpenAI's text-embedding-3-small, 8 pages per call (so 8 calls here), up to 24,000 characters per page.
  • For each page it gets back 1,536 numbers that describe what the page is about. Pages about similar things get similar numbers.
  • FAISS, on your computer, stores those numbers so it can compare them quickly later.
  • BM25, also on your computer, counts the words on each page. No AI is involved in this part.
  • The page text, the numbers and the word counts are saved in data/indexes/ under the file's fingerprint. Run the same file again and this whole step, including the embedding calls, is skipped.

The extractor never uses this index. It is for the QC checks.

Sent to OpenAI: the text of every page, to the embedding model.

The extractor reads the PDF and answers in JSON

gpt-4.1

The student answers every question, writes the page number and copies the sentence that proves it.

Python cuts the PDF into pages 1–40 and 41–60 and sends both pieces to gpt-4.1 at the same time, with the 14 fields and their descriptions. The instructions say: use only what is written, never guess or calculate, copy each value exactly as written, give the original page number and a word-for-word quote under 200 characters, include every line of an address, and return null if a field isn't there. A strict JSON schema forces the same answer shape every time, and temperature 0 keeps it as repeatable as possible.

The extractor fell for the trap and took the flood deductible from page 41. It also found no broker.

Sent to OpenAI: the PDF file in two pieces, plus the field list.

Python tidies up the answers

Pythongpt-4.1, only if needed

Before handing in the test, the student checks every copied sentence is really in the book.

  • Page numbers: AI page numbers can drift. Python looks for each quote, first in that piece's pages, then anywhere. Wherever the quote really is becomes the page number.
  • Merge: both pieces return all 14 fields. For each field Python keeps the most confident answer that isn't empty. Line breaks inside a value are joined into one line.
  • Self-check: a field whose quote can't be found anywhere goes back to gpt-4.1 once, in one call for all such fields, with the page's real text and a picture of it. The new answer is kept only if its quote is on the page, and the field's notes say a re-read happened. In our policy every quote is found, so this costs nothing.

Sent to OpenAI: usually nothing. Only for a self-check: the text and picture of the cited page.

QC checks, page by page

Pythongpt-4.1-minireranker

A second teacher, who did not write the answers, opens the book on the page the student named.

Python first finds each field's quote. Then there are three kinds of check, all running at the same time (up to 8 AI calls at once):

  • Page check: all fields whose quote is on the same page are checked together, in one call with that page's text. 10 fields on page 2 cost one call, not ten.
  • Absence check: fields the extractor left empty are searched for, then confirmed absent together in one text-only call.
  • Full check: any field those checks didn't confirm (a disagreement, a proof Python couldn't find, something found in an empty field) gets its own check with page pictures, a search and one re-ask. The next section shows it as a diagram.

Sent to OpenAI: to gpt-4.1-mini, the text of each page that holds fields (and a picture if it's a scan), the text of the pages searched for empty fields, and for full checks the text and up to 2 pictures of the pages read; to the embedding model, each search question.

Rule checks

Python

Does the answer add up?

  • A required field that is empty is flagged.
  • A number field must contain a number, and a date field a real date (day-first dates like 01/04/2026 are accepted).
  • The sum rule: ₹4,20,000 + ₹75,600 = ₹4,95,600, within the ₹1 the template allows. It passes. If it didn't, all three fields would be flagged with the difference.

Sent to OpenAI: nothing.

The report is saved

Python

For every field ParseProof saves the status, the extracted and checked values, both quotes, every page each quote appears on, the pages that were read, the notes, and the exact request sent to gpt-4.1-mini. It also saves the run's time, the number of AI calls, and the tokens per model, which the app turns into a cost. Everything goes into one database file, data/parseproof.db, on your computer.

Sent to OpenAI: nothing.

Inside one QC check

Most fields are settled by the cheap page check: one call per page, text only, for every field whose quote Python found on that page. A field counts as settled there only when the checker says “correct” and Python finds its proof on the page. Empty fields go to the absence check: a search for each, then one text-only call over those pages. A field confirmed absent is settled; a required one that's missing goes to Needs review. Everything else gets the full check below.

What gpt-4.1-mini is told and sent

It must reply in JSON: verdict, correct value, proof quote, proof page and reasoning. In the app, the QC request JSON button on every field shows the exact request and reply.

The policy number: the simple path

  • Locate (Python): “Policy No. NSI-CGL-2026-004512” is on page 2. Go to verify with page 2.
  • Verify (gpt-4.1-mini): reads page 2 and answers “correct”, with its own proof quote.
  • Check the checker (Python): the proof is on page 2. Decide: Verified.

One gpt-4.1-mini call, no search. Most fields go this way.

The deductible: why the checker must run even when the quote is found

  1. Locate (Python): “Flood deductible: ₹2,50,000 per occurrence” is on page 41, exactly. The sentence is real.
  2. Verify (gpt-4.1-mini), first try: reads page 41 and sees a flood add-on, not the policy's deductible. Verdict: not found on these pages.
  3. Search once (Python): the question “deductible · Deductible or self-insured retention amount · ₹2,50,000” returns pages 2, 7 and 18. How, step by step.
  4. Verify (gpt-4.1-mini), second try: reads pages 41, 2, 7 and 18 together and answers “incorrect, it is ₹50,000”, with the proof “Deductible: ₹50,000 each claim” on page 2.
  5. Check the checker (Python): the proof is on page 2, and the digits 50000 are in it. Decide: Mismatch. The review screen shows ₹2,50,000 crossed out and ₹50,000 suggested, with page 2 highlighted.

Python finding the quote is necessary, not enough

Python proves a sentence exists. Only an AI can tell whether that sentence answers the field. Without the checker, the flood deductible would have gone into the spreadsheet with a perfect quote beside it. So every field gets a gpt-4.1-mini check, and Python then checks gpt-4.1-mini's proof in turn.

The broker: a field that isn't there

  • Locate (Python): nothing was extracted, so there's no quote to look for. Go straight to search.
  • Search: the best 3 pages for “broker name · Insurance broker, agent or producer named on the policy”.
  • Verify (gpt-4.1-mini): not found. Broker isn't a required field, so it gets its own grey status, Not in document: nothing was extracted and nothing was verified, but it doesn't need a decision either. If it were required, it would be Needs review.

How Python checks a quote

Python's checks are the reason you can trust a quote: an AI could imagine a sentence, Python can't. Before comparing, Python lowercases both texts and squeezes all spaces and line breaks into single spaces. Then a quote counts as found on a page if any one of these is true:

CheckHow it worksExample from the policy
Forgiving Ctrl+Frapidfuzz partial_ratioFinds the closest stretch of the page and scores the match from 0 to 100. 85 or more counts as found, which allows odd spacing or a missing comma.“Policy No NSI-CGL-2026-004512” matches “Policy No. NSI-CGL-2026-004512” on page 2
Every piece on the pageFor a quote that spans lines the PDF stores apart: split it at commas, and accept it if every piece is on the page and together they cover almost all of the quote.A multi-line insured address
Words in orderAll the quote's words appear on the page in the same order, with at most 8 other words between any two. For blocks the PDF mixes with another column. Needs at least 4 words.An address whose lines are mixed with “Policy period” lines from the right-hand column
Shortened with “...”If the checker shortens a quote with “...”, every piece must be on the page, in order, exactly. A heading glued to a value from another line does not pass.“Coml Auto 24 8 ... $327,024 32.1%” passes; “Coml Auto ... Incurred $327,024” does not

Two more checks are stricter:

  • Numbers must match exactly. When the checker suggests a corrected value, every number in it must appear as a whole number in its proof quote. Leading zeros and commas don't matter (03/07/2026 matches 3/7/2026), but ₹5,000 does not match “Deductible: ₹50,000 each claim”, and a guessed 0 needs a real 0 in the proof.
  • One re-ask. If the checker's proof isn't on the page word for word, it is asked once more on the same pages: “copy one continuous piece of the page, a whole line or table row”. This shows in the Run report as a separate call.
  • Same value is not a mismatch. If the checker calls a value “incorrect” but its correction is the same value with different formatting (548867 and $548,867), it counts as verified.
  • Same words. If the checker's “correct value” has exactly the same set of words as the extracted value, with at least 4 words, it is the same value and counts as verified. This applies only to text fields, never to numbers or dates.

Python also uses these checks to find every page a quote appears on. A name printed in every page header shows as “Quote found on pages 1, 2, 3, 4” in the review screen, and each page number is a link.

How the search finds pages

This is the “RAG” part (Retrieval-Augmented Generation: find the right text first, then give only that to the AI). It runs only during a QC check, when the extractor's quote is missing or the checker says the value is wrong or not on its pages. The search question is the field name, its description and the extracted value: deductible · Deductible or self-insured retention amount · ₹2,50,000.

60pages

FAISS: search by meaning. The question is sent to text-embedding-3-small and comes back as 1,536 numbers, the same way every page did in step 4. FAISS compares those numbers with all 60 pages' numbers (cosine similarity, on your computer) and lists the 10 closest in meaning. It finds pages about deductibles even if they say “self-insured retention”.

60pages

BM25: search by words. At the same time, every page gets a score for how often it uses the question's words. Rare words count more than common ones, and long pages don't win just by being long. It catches exact things meaning search can miss, like “₹2,50,000”. Top 10, ignoring pages with no matching word.

≤10pages

RRF: merge the two lists. Each list gives a page 1 ÷ (60 + its rank) points and the points are added. A page high on both lists rises to the top. The best 10 go on.

3pages

Reranker: read carefully. The small model ms-marco-MiniLM-L-6-v2, running on your computer, reads the question and each page side by side and scores the match. Pages longer than 1,500 characters are read in overlapping windows of 1,500 (300 overlap), and a page's score is its best window. The best 3 pages not already read go to the checker.

Why not only FAISS and BM25?

They are fast but rough. Each makes its fingerprint of the question and of the page separately, so neither ever reads them together.

Why not only the reranker?

It is the most accurate and the slowest. Reading 10 pages is quick; reading all 60 for every search is not. So FAISS and BM25 pick 10 and the reranker picks 3.

Checking page by page cut the QC cost by about 85%

Before, every field got its own call with the page's text and picture, so a page with 10 fields was sent 10 times. On the 9 loss runs, QC cost 155% of extraction. Now one call checks every field on a page, text only, and only unconfirmed fields get a full check with pictures: QC is 24% of extraction, with the same results. Choosing the checker model matters too: with gpt-4o instead of gpt-4.1-mini, the checker's token price is about six times higher.

If cost matters

  • The checker is already the cheap model. For the strongest check, set the QC model to gpt-4o under Settings, at about five times the QC cost. Most of the bill is now extraction, which grows with page count.
  • Fewer fields: fields on the same page share one check, so fewer fields mostly saves extraction output and full checks.
  • Fewer pages: if you only need the first 10 pages of a 200-page contract, upload those.

Is this an AI agent?

Strictly, no. An AI agent is a model that decides its own next step in a loop: it picks a tool, looks at the result, and decides again until it thinks it's done. ParseProof is an AI workflow: the steps are fixed in code, the AI does a job inside a step, and the code decides what happens next. The code calls the parts “the extraction agent” and “the QC agent”, but that is a loose name.

PartWho decides the next step
ExtractionThe code: one call per 40 pages
Self-checkThe code: only when Python can't find a quote
QC checkThe code: locate, verify, search again only if the verdict is wrong or not found, then decide. gpt-4.1-mini judges; Python reads its answer and steers.
Search, rules, exportPlain code

LangGraph, the library that runs it, is often used to build agents; here it wires a fixed workflow with branches and parallel steps. That choice keeps cost predictable (at most two checker calls per field), makes every field auditable (same steps every time, all shown on screen), and keeps runs repeatable. A one-line description: ParseProof is an AI workflow built with LangGraph: one AI extracts, a second AI checks each field on its source page, and Python verifies both of them.

You upload the file

The browser sends the file to the server. The server saves it under a new id, refuses types it can't read, files over 100 MB and locked PDFs, and records it in SQLite. Nothing goes to OpenAI yet.

@app.post("/api/documents")
def upload_document(file: UploadFile = File(...)):
    ext = Path(file.filename or "").suffix.lower()
    if ext not in ALLOWED_TYPES:                      # .pdf .docx .xlsx .xls .csv .txt
        raise HTTPException(400, f"Unsupported file type '{ext or 'none'}'. Use PDF, Word, Excel, CSV or text.")
    doc_id = db.new_id()
    path = DOCUMENT_DIR / f"{doc_id}{ext}"            # data/documents/<id>.pdf

The pipeline is a LangGraph graph

Python

Every box in the code map above is one add_node line. A plain edge always goes to the next node. A conditional edge calls a Python function that decides where to go; when it returns a list of Send(...), LangGraph runs that node once per item, in parallel (8 at a time), and adds up their outputs.

    g = StateGraph(PipelineState)
    g.add_node("ingest", ingest)
    g.add_node("extract_batch", extract_batch)
    g.add_node("merge_extraction", merge_extraction)
    g.add_node("ground_extraction", ground_extraction)
    g.add_node("qc_page", qc_page)
    g.add_node("qc_direct", qc_direct)
    g.add_node("qc_absent", qc_absent)
    g.add_node("qc_followup", lambda state: {})
    g.add_node("qc_field", qc_field)
    g.add_node("rules", rules)
    g.add_node("report", report)
    g.add_edge(START, "ingest")
    g.add_conditional_edges("ingest", route_after_ingest, ["extract_batch", "qc_page", "qc_direct", "qc_absent", "rules"])
    g.add_edge("extract_batch", "merge_extraction")
    g.add_edge("merge_extraction", "ground_extraction")

    g.add_edge("qc_page", "qc_followup")

    g.add_conditional_edges("qc_followup", followup_sends, ["qc_field", "rules"])
    g.add_edge("qc_field", "rules")
    g.add_edge("rules", "report")
    g.add_edge("report", END)
    return g.compile()

Build the page index: embeddings, FAISS and BM25

Pythontext-embedding-3-small

Each page is one search unit, so every answer can point at an exact page. The first 24,000 characters of every page go to OpenAI's embedding model, 8 pages per call; each page comes back as 1,536 numbers that capture its meaning. FAISS stores those numbers. BM25 stores word counts for keyword search. Both are built once per file and saved.

doc_index.pyPageIndex
class PageIndex:
    def __init__(self, pages):
        self.pages = [p or "" for p in pages]
        texts = [p[:EMBED_CHARS] if p.strip() else "[empty page]" for p in self.pages]   # 24,000 chars
        self.faiss = build_faiss_index(create_embeddings(texts))
        self._prepare()

    def _prepare(self):
        self._norm = [normalize(p) for p in self.pages]                  # lower case, single spaces
        self.bm25 = BM25Okapi([tokenize(p) or ["_"] for p in self.pages])  # words per page

    def save(self, folder):                                              # pages.json + pages.faiss
        (folder / "pages.json").write_text(json.dumps(self.pages), encoding="utf-8")
        faiss.write_index(self.faiss, str(folder / "pages.faiss"))
vector_store.pycreate_embeddings() and build_faiss_index()
def create_embeddings(text_chunks, batch_size=8):
    for i in range(0, len(text_chunks), batch_size):
        batch = text_chunks[i:i + batch_size]
        resp = client.embeddings.create(model=EMBED_MODEL, input=batch)  # text-embedding-3-small
        for itm in resp.data:
            embeddings.append(np.array(itm.embedding, dtype=np.float32))  # 1,536 numbers per page
    return np.vstack(embeddings)

def build_faiss_index(emb):
    faiss.normalize_L2(emb)            # length 1, so inner product = cosine similarity
    idx = faiss.IndexFlatIP(DIMS)      # exact search over every page, no approximation
    idx.add(emb)
    return idx

Search: FAISS + BM25, merged with RRF, then reranked

text-embedding-3-smallPythonreranker

The question is embedded (one small call) and FAISS returns the 10 pages closest in meaning. BM25 returns the 10 pages with the best keyword score. RRF merges the two lists: a page gets 1/(60 + rank) from each list it is in. The top 10 then go to the cross-encoder on your computer, which reads the question and the page together in windows of 1,500 characters; a page's score is its best window. The best 3 pages are returned.

    score = fuzz.partial_ratio(q, self._norm[p - 1])          # 0-100
    if score > best_score:
        best_page, best_score = p, score
if best_score >= threshold:                                   # QUOTE_MATCH_THRESHOLD = 85
    return best_page, best_score
for p in candidates:
    page = self._norm[p - 1]
    if segments_on_page(q, page) or words_in_order(q, page) or pieces_in_order(q, page, threshold):
        return p, float(threshold)
return None, best_score

NUMBER = re.compile(r"\d[\d,]*(?:\.\d+)?")

def value_in_quote(value, quote):
    wanted = numbers_in(str(value))                           # "₹50,000" -> [50000.0]
    if wanted:
        in_quote = set(numbers_in(quote))                     # whole numbers, so 0 must be a real 0
        return all(n in in_quote for n in wanted)
    return fuzz.partial_ratio(normalize(value), normalize(quote)) >= QUOTE_MATCH_THRESHOLD

Decide the status

Python

The model gives a verdict; Python decides the status. A correction that only reformats the same value (₹4,95,600 vs 495600, or an address with its city printed twice) counts as verified, so a comma is never a mismatch.

elif v == "not_found" and is_empty(ex.get("value")) and not spec.get("required"):
    status = ABSENT                                 # Not in document
else:
    status = REVIEW                                 # Needs review: no proof either way

More questions people ask

Why do two runs of the same document sometimes give different answers?

An AI writes its answer one small piece at a time and takes the most likely next piece. When two choices are almost tied, tiny differences on OpenAI's servers can tip it either way, even at temperature 0. No setting makes any AI model 100% repeatable. The self-check, the second AI and Python's proof checks are there to catch a slip before it reaches your spreadsheet.

Can it still be wrong?

Yes, mainly when both AIs make the same mistake and the proof is a real sentence. The checker is a separate model that reads only the relevant pages, which makes that rarer. gpt-4.1 and gpt-4.1-mini come from the same model family, so for the most independent check, switch the checker to gpt-4o. Anything uncertain is marked Needs review rather than guessed.

Does it work on scans and photos?

Yes. The extractor reads the page pictures in the PDF, and OCR makes the scanned pages searchable for QC. Scanned pages have no text layer in the viewer, so the proof shows as a quote in the field panel instead of a highlight on the page.

Can it read tables with many rows, like every line item or every claim?

Not yet. Each field is one value. For repeating data, use summary fields that are written on the document, such as totals, counts or the largest item.

What about password-protected PDFs?

They are refused at upload with a clear message. Open the PDF, print it to a new PDF (Print → Save as PDF) and upload that copy.

Where is our data stored?

On the computer running ParseProof: files in data/documents/, indexes in data/indexes/, everything else in data/parseproof.db. None of it is in the GitHub repository. What goes to OpenAI is listed in What is sent to OpenAI.

Can we use other models?

Yes. Under Settings → Model prices, add the model with its input and output price; it then appears in the pickers for extraction, QC and OCR. A model without a price is left out of the cost total, and the app says so.
